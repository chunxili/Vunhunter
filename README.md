# VunHunter

基于《VunHunter PRD v1.0》的企业威胁情报与漏洞闭环管理系统，当前交付为可本地运行的功能演示 MVP。前端采用 React 19、Vite 和 Lucide，后端采用 Express，业务数据通过原子写入持久化到本地 JSON。

## 启动

需要 Node.js 20.19+，在项目目录运行：

```powershell
npm install
npm run dev
```

打开 http://127.0.0.1:5173 。开发模式后端为 3001 端口；修改后端后需要重启。前端支持热更新。

使用正式构建进行本地演示：

```powershell
npm run build
npm start
```

打开 http://127.0.0.1:3001 。默认只监听本机回环地址。

## 体验路径

1. 总览查看风险指标、风险分布、项目风险和 SLA 超期任务。
2. 情报中心筛选 CVE，打开智能分析报告；人工确认后创建站内通报。
3. 在修复看板点击任务，按“已通报 → 已确认 → 修复中 → 验证中 → 已关闭”推进；关闭任务可填写原因后重开。
4. 项目与资产页查看 5 个项目、61 个组件和 92 台服务器，导入精确版本 SBOM。
5. 知识图谱支持节点拖拽、关系高亮、漏洞筛选及全屏模式；全局安全 Agent 可查询 CVE 影响项目与公网暴露面。
6. 报告内提交评分及评论，左下角切换为“产品经理”，在 PM Toolkit 查看 VOC、用户画像和需求跟踪矩阵。
7. 右上角导出项目风险 CSV；分析报告底部通过浏览器打印功能保存 PDF。

## 数据与角色

- 左下角的角色切换是**演示身份入口**。服务端使用 HttpOnly 会话 Cookie，校验操作角色并隔离开发/运维角色的项目、任务和服务器。
- 安全负责人负责通报和源配置；研发仅访问电商/增长项目；运维访问电商/支付/分析/DevOps；IT 总监查看全局态势；PM Toolkit 数据只返回给 PM。
- 这不是生产身份认证或多租户实现。没有 SSO、真实用户凭证、租户数据库隔离或存储加密，不能直接用于承载真实企业机密数据。
- 数据文件为 `data/db.json`，自动生成且不纳入 Git。`DATA_DIR` 可指定独立数据目录。会话保存在内存，服务重启后刷新页面会重新创建演示会话。
- 初始数据是合成演示数据；样例 CVE 的描述、影响范围、版本建议和日期不能作为生产安全判断。
- SBOM 支持 CycloneDX JSON、SPDX JSON、package.json、pom.xml 和 go.mod。最大 2MB；导入替换当前项目清单。版本范围、属性变量及依赖解析需要上游构建工具生成精确清单，不能当作实际安装版本。
- 匹配依据组件名和 SemVer 区间，未实现完整 CPE/PURL 别名、Maven/Go 特殊版本语义、传递依赖及可利用性核验。

## 实现边界

已实现数据库保存、站内通报、任务状态机、审计、角色校验、SBOM 解析匹配、评分权重、结构化资产查询、VOC 保存和规则示例归类。

外部 NVD/CNVD/GitHub 采集、RSS 拉取、LLM、邮件/企业微信/短信/电话服务尚未接入。刷新情报仅刷新本地关联，报告是透明标记的模板报告，Agent 是结构化规则查询，需求工厂是规则示例归类。配置情报源只保存地址，不执行网络采集。图谱为内存关系投影，页面展示可操作的摘要节点，不声称已运行 Neo4j 或拥有 253 个实体。服务器页面使用项目关联，不声称完成了主机实际软件安装扫描。

趋势图标注为演示历史。风险分布、关联项目、任务计数和修复进度从当前数据计算。MTTR 在无已记录关闭时间时显示明确标记的演示基线；有实际完成记录后按时间戳计算。CSV 是项目态势快照；PDF 为分析报告打印，不是延期范围的合规审计报告。

PRD 的实时采集 SLA、准确率 >95%、千台主机性能、99.5% 可用性、企业级 TLS/存储加密及多租户目标尚未验证或实现。上线前需接入身份系统、生产数据库/队列、密钥服务及监控，并验证数据源授权、版本语义和实际资产发现能力。
